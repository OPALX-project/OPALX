# BeamBeam interaction redesign state

Updated: 2026-08-19

## Goal

Make BeamBeam an ordinary placed OPALX element at the parser, representation,
placement, visitor, and ownership levels while moving its stateful collective
execution out of `ParallelTracker`. Preserve the merged BeamBeam physics and
numerical behavior.

The current follow-on goal is a controlled reduced-order validation model with
two prescribed rigid primary Gaussians. First compare E and B, then use the same
fields to compare time-emitted electron/positron trajectories.

## Implementation sequence

1. Baseline and coupling inventory: complete.
2. Generic element-interaction contract: complete.
3. Generic per-run interaction manager: complete.
4. BeamBeam runtime extraction: complete.
5. Generic Tracker phase wiring: complete.
6. Tests and architecture documentation: complete.
7. Full build, MPI validation, and final diff review: complete.

## Design decisions

- `ElementBase::createInteraction()` defaults to no interaction. Local field
  elements continue to use `ElementBase::apply()`.
- A placed `BeamBeam` overrides the factory and creates a
  `BeamBeamInteraction`.
- `ElementInteractionManager` retains each placed element and owns its mutable
  interaction for one tracking run.
- `ParallelTracker` dispatches only generic `SelfField`, `AfterEmission`, and
  `Diagnostics` phases and queries generic fixed-mesh/default-solve capability.
- `ElementInteractionContext` is explicitly documented as a non-owning,
  dispatch-scoped view, including phase-specific service availability and the
  reference-frame/beam-frame transformation semantics.
- The BeamBeam interaction owns lifecycle, actual placed geometry, saved field
  domain, source/witness state, timers, and diagnostic state.
- `PartBunch` remains the owner of the lower-level field-domain, mesh,
  deposition, solve, and gather mechanisms.

## Physics and numerics

- No formulas, units, element boundary rules, mesh-cell convention, copy-time
  rule, source retirement rule, witness selection, or diagnostic schema changed.
- Source deposition, Poisson solve, field gather, and coordinate-transform order
  are unchanged.
- No tolerance changed. The copied-charge check remains
  `max(1e-18 C, 1% of expected charge)`.
- No Kokkos kernel, MPI collective, reduction order, OpenMP scheduling, or data
  movement was changed by the extraction.

### Reduced-order rigid-source mode

- New `BEAMBEAM` option `BBRIGID` defaults to `FALSE`, preserving the existing
  self-consistent primary-source response.
- With `BBRIGID=TRUE`, source container 0 still deposits charge. After the solve
  and frame transform, only the source particles' sampled E and B are cleared;
  the mesh field remains available to passive witness containers. After
  `COPY_TIME`, the binned field contains both the physical and mirrored primary
  sources.
- External element fields, ordinary drift/tracking, copied-source construction,
  and witness gathering are unchanged. Therefore `BBRIGID` alone does not force
  an arbitrary input distribution to remain Gaussian; the reduced-model deck
  also uses negligible divergence/momentum spread and no external focusing.
- No field equation, unit, solver tolerance, Kokkos reduction, or MPI ordering
  changed. The additional source E/B assignments execute in the active Kokkos
  memory space and are fenced before tracking continues.
- The independent smooth model uses two identical 245 MeV electron Gaussians,
  each with 1.25e10 electrons and lab rms sizes sigma_x=sigma_y=
  1.944325075701 um and sigma_z=0.6 mm. Their centers are at +/-d/2 around the
  IP and move toward one another. Snapshots use d/sigma_z = 3, 2, 1, 0.
- Pair fields are excluded. The analytic evaluator uses the uniform-motion
  Lorentz transform of each triaxial rest-frame Gaussian.

## Confirmed physics contract

- The application is a gamma-gamma collider. Gamma collisions create
  electron/positron pairs around the BeamBeam interaction point.
- The charged primary electron bunches remain present near the IP, and their
  electromagnetic fields influence the pair trajectories.
- The IP is exactly the midpoint of the BeamBeam element; `IP_S` is not part of
  the intended model.
- For the first implementation, externally generated pair phase-space records
  are imported rather than generated by OPALX.
- Pair emission is time-dependent: every imported particle retains its own
  creation time and is emitted at that time and supplied position around the
  IP.
- The pairs are passive witnesses. They sample the primary field but do not
  deposit charge, produce pair self-fields, interact collectively with each
  other, or back-react on the primary beams.
- The physical primary container is both source and target: it deposits charge
  and receives the collective field from the physical and mirrored
  counter-propagating primary contributions. The second primary is evolved
  implicitly through the imposed mirror symmetry, not as an independent
  particle container.
- A later internal Breit-Wheeler generator should feed the same time-dependent
  emission interface.

Implementation findings and remaining gaps:

- Resolved: the BeamBeam copy model had been implemented only in
  `computeLegacySelfFields()`. The binned path now deposits the mirrored
  same-sign source about the element midpoint, solves it separately, reverses
  the longitudinal mean momentum for the lab transform, restores physical
  source positions, and records the deposited-charge diagnostic. No
  non-BeamBeam solve takes the added charge-reduction path.
- The relativistic binned solve stretches the longitudinal cell by the bin
  Lorentz factor. The reduced model must use `GREENSF=INTEGRATED`; at gamma
  480.453 the rest-frame cell aspect ratio is about 190000:1 and the
  point-cell `STANDARD` kernel is not a valid discretization for this mesh.
- Remove or neutralize the current `IP_S` override so midpoint geometry is
  authoritative.
- Do not create a new time-dependent emission mechanism: `EMITTEDFROMFILE`
  already implements sorted per-particle birth times, step-wise emission, and
  fractional birth-step integration.
- Reconcile the existing timed gamma-gamma file format
  (`x y z px py pz t bin_number`) with the old-OPAL positional format currently
  accepted by `EmittedFromFile` (`x px y py t pz [bin]`). The prototype
  `gamma_gamma_pairs-3.in` currently fails at this boundary. The repair must
  also define how the converter's `t = ct/c` maps to absolute birth time and
  preserve the explicit per-record creation `z`; the current old-OPAL reader
  negates/recenters file time and places every emitted particle at source
  `R0Z`.
- Once that integration is repaired, migrate and validate the current
  large-cylinder physics decks, which still use common-`T0` `FROMFILE`
  injection, on the existing `EMITTEDFROMFILE` path.

## Persistent rigid-field regression procedure

Use two complementary test levels rather than committing generated H5 files as
golden data.

### Fast invariant test

- Keep the focused C++ exact-overlap test in
  `unit_tests/PartBunch/TestBinnedFieldSolver.cpp`.
- It verifies that the copied-primary pass doubles the deposited charge,
  restores every physical source coordinate exactly, doubles E for a
  z-mirror-symmetric source, and cancels B.
- Register and run both a normal one-rank CTest instance and an explicit
  two-rank instance. This test is deterministic, fast, and does not write H5.

### End-to-end manufactured-field test

- `TestBeamBeamManufacturedFields` now generates the 3-sigma input and
  deterministic 51x101 probe file in an isolated CTest working directory. The
  101x201 grid remains the detailed plotting/diagnostic default.
- Run the two-step rigid-source OPALX case with `GREENSF=INTEGRATED`.
- Disable the large source-container H5 output with `C0PSDUMPFREQ=0`; retain
  `PSDUMPFREQ=1` and `EBDUMP=TRUE` for the passive witness container.
- Read the physical-source centroid from the small `_c0.stat` file and read the
  probe positions and E/B values from `Step#1` of `_c1.h5`.
- Generate the smooth two-Gaussian manufactured fields at those actual probe
  coordinates and compare vector fields directly.
- The CI checker must not create plots on the success path. It should print a
  compact metric table, write an optional summary CSV below the build tree, and
  return nonzero when an assertion fails. Plot generation remains available for
  local diagnosis or CI failure artifacts.
- Check in only the template, parameters, checker, and tolerance configuration.
  Do not check in generated H5, STAT, CSV field tables, logs, cache files, or
  PNGs.

```text
relative L2(E) < 0.03
relative L2(B) < 0.03
0.97 < median |E|_OPALX / |E|_manufactured < 1.03
0.97 < median |B|_OPALX / |B|_manufactured < 1.03
```

Use statistical/physics tolerances, not exact stored arrays: the primary bunch
is sampled from a seeded Monte Carlo distribution, and OpenMP/MPI decomposition
may change reduction order or the sampled distribution. The thresholds must be
wide enough for supported execution modes but tight enough to detect the former
factor-5000 field amplification.

### Current output schema and units

- `PSDUMPFREQ=1` writes every tracking step and `EBDUMP=TRUE` adds sampled E/B.
- OPALX writes one H5Part file per container. Each `Step#N` contains `float64`
  arrays `x`, `y`, `z`, `Ex`, `Ey`, `Ez`, `Bx`, `By`, `Bz`, `q`, and `id`, plus
  attributes including `TIME`, `SPOS`, `RefPartR`, and `GlobalTrackStep`.
- Coordinates are stored relative to the container reference particle. The
  current comparator reconstructs absolute longitudinal position as
  `z_absolute = RefPartR[2] + z`.
- The detailed 3-sigma run writes about 96 MB for the 400000-particle `_c0.h5`
  and 4.7 MB for the 20301-probe `_c1.h5`. The persistent 5151-probe test writes
  about 1.2 MB for `_c1.h5`. Disabling container-0 particle dumps and using
  `_c0.stat` replaces the 96 MB file with a roughly 4.4 KB metadata-only H5
  shell containing no `Step#N` groups.
- `H5PartWrapperForPT` writes `pc->E` directly, so the stored electric-field
  numbers are in V/m; B is in T. The current H5 root attributes incorrectly
  label `ExUnit`, `EyUnit`, `EzUnit`, and `E-refUnit` as `MV/m`. The comparator
  currently interprets the numerical E data as V/m. Correcting the metadata in
  the master-derived H5 writer requires explicit permission and a downstream
  compatibility audit.

The first A100 fixed-source chain used jobs 353967/353968/353969. The one- and
two-rank cases completed in 6 s and 9 s. The four-rank physics completed both
BeamBeam solves, then hung during object teardown and was canceled after stack
capture. Every rank was inside collective `MPI_Win_free` from
`ParticleSpatialLayout::~ParticleSpatialLayout`, but rank 0 reached it through
`PartBunch::~PartBunch` while ranks 1--3 reached it through a particle-container
`shared_ptr` released by `ParallelTracker::~ParallelTracker`. Thus different
ranks were freeing different MPI windows in the same collective slot.

Two lifetime defects explain this. `Distribution::emitting_m` has no initial
value and `setDist()` does not set it for `GAUSS` or `FROMFILE`, so an injected
file sampler can be retained as an emitting sampler depending on indeterminate
memory. Separately, `TrackRun` declares the tracker before the bunch, which
causes automatic member destruction to destroy the borrowed bunch before the
tracker and its sampler references. The required source fix is to initialize
and reset `emitting_m=false` before distribution-type setup, and explicitly
destroy `itsTracker_m` at the start of `TrackRun::~TrackRun`, before automatic
bunch destruction. Both are lifetime/control-state corrections only: they do
not change fields, units, deposition, solver order during tracking, or particle
physics. Because these are master-derived files, implementation awaits explicit
permission under the merge rule.

Two failures exposed by the scan were resolved as follows:

- The 100000- and 200000-particle CUDA cases derived the BeamBeam end from an
  OrbitThreader range clipped by the short tracking horizon (about 8.9 mm), not
  from the physical 16 mm element. A sampled bunch head crossing that artificial
  end caused the particle-count-dependent `Completed` transition. The
  interaction now uses `ELEMEDGE` plus the declared element length as its
  authoritative path-length window; the threaded range is only used to discover
  the element and as the entrance fallback for 6D-pose placement. Job 353953
  confirmed `s_range=(0.000, 0.016)` m and `Active` on both solves for the exact
  100000-particle A100 reproducer. Its Step#1 result is L2(E)=2.5247%,
  L2(B)=2.6614%, median E/B ratios 1.00262/1.00369, direction cosines
  0.9999832/0.9999801, and zero uncovered probes.
- The apparent two-rank shutdown defect was outside OPALX. Slurm accounting for
  canceled job 353949 shows both OPALX ranks (`353949.9` and `.10`) completed
  successfully in 19 seconds; only the nested `mpiexec`/PRRTE parent in the
  mixed four-GPU batch remained alive. Plain multi-task `srun` is not a valid
  workaround on Merlin: Slurm provides PMI2 while this Open MPI build expects a
  PMIx server, so jobs 353954, 353955, and 353957 started independent MPI
  singletons and are discarded as multi-rank evidence. A dedicated two-task,
  two-GPU allocation using the cluster's Slurm-aware `mpiexec -n 2` reported
  `MPI_Comm_size=2` and returned normally for the corrected 400000-particle
  full deck (jobs 353956 and 353958; measured runtime 7.04 seconds). Job 353959
  likewise passed all 13 focused BeamBeam tests on both real MPI ranks in 7
  seconds. The persistent driver therefore uses independent dependent
  allocations and `mpiexec` for every multi-rank stage; no OPALX source change
  was needed for this launcher-level defect.
- The first full four-rank runs (353962 and 353964) exposed a real collective
  mismatch. Ranks with zero locally owned witness particles skipped
  `gatherCurrentFieldsToContainer()`, while ranks owning witnesses entered its
  IPPL halo exchange. Stack capture showed ranks 0/2 waiting in halo receives
  and ranks 1/3 already waiting in the next `DistributionMoments` all-reduce.
  `BeamBeamInteraction::gatherFieldsToWitnessContainers()` now skips only a
  globally empty witness container; zero-local-particle ranks still enter the
  distributed gather with a zero-length particle range. Job 353965 completed
  both tracking solves on four ranks/four A100s in 9.41 seconds. This changes no
  field discretization, units, or particle physics; it restores identical MPI
  collective order on every rank.

The first automated submission also revealed a script-only stdin error: the
background `srun` steps inherited the manifest file descriptor and consumed
unread labels. The driver now redirects each background step from `/dev/null`;
job 353963 recovered and completed all skipped cases. The final workflow also
times the rank-one baseline alone before launching concurrent cases and records
the executable hash plus exact tracked OPALX source patch.
